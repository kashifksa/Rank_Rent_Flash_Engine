## HARD RULES — NEVER BREAK THESE

### 1. KEYWORD SILO RULE
- Primary keyword (e.g. "Sprinkler Repair Denton TX") → Homepage ONLY. Mark as RESERVED.
- Every other page gets its own UNIQUE primary keyword.
- No two pages may share the same primary keyword.
- Before finalizing any page keyword, cross-check the full list.

### 2. SERVICE PAGE LOCATION RULE
- Service pages mention the PRIMARY CITY ONLY in H1 and body content.
- Example: H1 = "Sprinkler System Installation in Denton, TX"
- NEVER mention surrounding cities in a service page hero or body.
- Surrounding cities get their own dedicated location pages.

### 3. LOCATION PAGE CONTENT RULE (70/30)
- 70% same structure across all location pages (services, process, FAQ, CTA)
- 30% must be unique per city: intro paragraph, local landmarks,
  neighborhoods, zip codes, meta title, meta description
- Every location page lists ALL services with short descriptions
- Location pages interlink back to main service pages

### 4. AREAS WE SERVE — HOMEPAGE ONLY
- Homepage "Areas We Serve" section = city names + internal links ONLY
- No detailed content about surrounding cities on the homepage
- Each listed city links to its dedicated location page

### 5. PRICING RULE
- Never include pricing, cost estimates, or service charges on any page by default
- This is a Rank & Rent site — the service provider sets their own prices
- NEVER USE: "starting from $X", "costs $X", "affordable", "cheap", "lowest price"
- Pricing page is OPTIONAL — only if service provider explicitly requests it
- If created, it goes on an inner page only — never homepage

### 6. NO CANNIBALIZATION RULE
- Before assigning any keyword, check the full keyword list
- If two pages would target the same keyword, resolve before outputting
- Cannibalization resolution: assign broader keyword to parent page,
  narrow/long-tail to child page

### 7. INTERNAL LINKS RULE
- Anchor text for each destination page must be IDENTICAL across all pages
- Standardize one anchor text per destination URL
- Internal links only point to pages that exist in the blueprint
- Placeholder links allowed for pages not yet published

### 8. NAP CONSISTENCY RULE
- NAP (Name, Address, Phone) is read from master_brief.json ONCE
- Used identically on every page in schema, contact section, and footer
- Never invent or vary NAP data

### 9. IMAGE NAMING RULE
- All images: WebP format
- Naming: [primary-keyword]-[city]-[state]-[description].webp
- Logo: [company-name-hyphenated]-logo.webp (transparent background)
- Favicon: [company-name-hyphenated]-favicon.webp (transparent background)

## STEP-BY-STEP BLUEPRINT INSTRUCTIONS

### STEP 1 — READ MASTER_BRIEF.JSON
Extract and store these values — they flow into EVERY page:
- `company_name`, `nap`, `niche`, `primary_city`, `state`, `primary_keyword`
- `tone` block → used by Prompt 7 for all writing
- `entity_map` → used for entity coverage per page
- `competitor_intelligence` → used to identify gaps per page
- `ai_search_strategy` → used for AI optimization per page
- `eeat_requirements` → applied to all pages

---

### STEP 2 — BUILD KEYWORD MASTER LIST
Go through every page in `topical_authority.json`.
Assign one unique primary keyword per page.
Rules:
- Homepage primary keyword → RESERVED. No other page may use it.
- Service pages: [Service Name] + [Primary City] + [State]
- Location pages: [Primary Service] + [Location City] + [State]
- Blog/informational: long-tail question or informational keyword
- After assigning all keywords, cross-check the full list for duplicates.
- If duplicates found, resolve before proceeding to Step 3.

---

### STEP 3 — STANDARDIZE ANCHOR TEXTS
For every page in the blueprint, define:
- The standard anchor text all other pages will use to link to it
- One alternate anchor text variation
- These are fixed — Prompt 7 must use exactly these anchor texts

---

### STEP 4 — BLUEPRINT EACH PAGE
For every page in every phase, complete the full blueprint object:
- SEO meta (title, meta description, H1, slug, canonical)
- Keyword strategy (primary, secondary, long-tail, questions, LSI)
- Page structure with all sections defined
- Local SEO (neighborhoods, landmarks, weather, NAP placement)
- Internal linking (outbound + which pages link to this one)
- Schema types required
- E-E-A-T signals per section
- AI search optimization format per section
- FAQ list (questions + answers from PAA, Reddit, Quora, YouTube)
- Conversion strategy (CTA placement and text per section)

Apply all HARD RULES throughout.

---

### STEP 5 — BUILD INTERNAL LINK MAP
After all pages are blueprinted:
- Map every internal link: source page → destination page → anchor text
- Ensure every page receives at least 2 inbound internal links
- Ensure homepage links to all Phase 1 pages
- Ensure Phase 1 service pages link to Phase 3 location pages (placeholder links for pages not yet published)
- Verify anchor texts match the standardized list from Step 3

---

### STEP 6 — QUALITY CHECKLIST
Before outputting, verify all items in `quality_checklist`.
If any item is FALSE, fix it before outputting.
List all `quality_notes` for the content writer.
